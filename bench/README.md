# Набор замеров

Замеряется своя работа, а рядом — то же по роду работы у OpenSSL: хеш против хеша,
поточное шифрование против поточного, шифрование с проверкой целостности против
такого же, подпись и обмен ключами на кривой против кривой.

Алгоритмы при этом разные — ГОСТ у нас и не ГОСТ у эталона. Сличается здесь **не
совпадение итога, а цена работы одного рода**: правильность проверяется вектором из
текста стандарта, а замер отвечает на другой вопрос — во что эта работа обходится.

## Сборка и запуск

```bash
cmake -S . -B build-release -DCMAKE_BUILD_TYPE=Release -DCMAKE_BUILD_BENCHMARKS=ON
cmake --build build-release --target bench -j
./build-release/bench/bench
```

Ключи:

| Ключ | Умолчание | Назначение |
|---|---|---|
| `CMAKE_BUILD_BENCHMARKS` | `OFF` | Собирать набор замеров |
| `CMAKE_BENCHMARK_OPENSSL` | `ON` | Сличать замеры с эталоном OpenSSL, если он в системе есть |

Эталона в системе может и не быть: тогда набор соберётся без сличения и покажет одни
свои замеры.

## Правила замера

* **Только сборка Release.** Отладочная сборка замедляет всё разом и ровно, изображая
  точечную просадку там, где её нет.
* **Замер берётся лучшим из шести прогонов, а не средним.** Середина ряда ловит чужую
  нагрузку машины, тогда как лучший прогон — это цена работы, а не цена соседства.
* **Замеряемая работа обязана удаваться.** Молчаливый отказ меряется мгновением и
  выдаёт полосу, которой не бывает: первый же прогон здесь показал у MGM 190 ГБ/с —
  ровно оттого, что режим не завёлся и работы не было вовсе.
* **Эталон запускать и без ускорения.** На своих алгоритмах он идёт машинными
  командами, которых у ГОСТ нет ни на одной машине; чтобы сличить сами алгоритмы, а не
  оснастку под них, ускорение отключается:

```bash
OPENSSL_armcap=0 ./build-release/bench/bench                      # ARM
OPENSSL_ia32cap=~0x200000200000000 ./build-release/bench/bench    # x86-64
```

## Состав примитивов и оговорки эталона (03.11.2026)

Набор охватывает примитивы всех кругов библиотеки: хеши (Стрибог, SHA-2, SHA-3, SM3,
RIPEMD-160), шифры (Кузнечик и Магма в CTR и MGM, AES в CBC/GCM/CCM, ChaCha20,
ChaCha20-Poly1305, SM4-GCM, DES-EDE3-CBC), имитовставку UMAC-128, подписи (ГОСТ 34.10,
RSA-PSS, ML-DSA-65, Ed25519, Ed448, SM2, SLH-DSA-128s) и обмены ключами (ECDHE, ECDH
P-256, X25519, X448, VKO, FFDHE modp2048, упаковка и распаковка ML-KEM-768).

Эталонные ветви новых строк берутся из провайдеров OpenSSL по имени (`EVP_MD_fetch`,
`EVP_CIPHER_fetch`) и при отсутствии алгоритма у эталона печатают пропуск сличения —
так, FreeBSD несёт OpenSSL без SM3 и SM2, Astra (3.4) — без ML-DSA и SLH-DSA, а сборка
ML-KEM у эталона появляется лишь с издания 3.5 и под младшими изданиями отрезается
на этапе компиляции. Двух строк эталона нет вовсе: SM4-GCM и UMAC OpenSSL не несёт,
оттого они печатаются только своей работой. На стендах без OpenSSL (Эльбрус, Windows
11 ARM64) набор собирается без сличения целиком.

## Сценарии протокола (06.09.2026)

Помимо примитивов набор меряет саму связь - обе стороны в одном процессе, байты и
дейтаграммы перекладываются из рук в руки, сети нет. Всякая работа прежде замера
проводится один раз и обязана удаться: молчаливый отказ выдал бы полосу, которой нет.

| Сценарий | Что меряется | Единица |
|---|---|---|
| Рукопожатие TLS 1.3 | полное рукопожатие с самоподписанным сертификатом ГОСТ | раз/с |
| RSA CKE годный/порченый | стойкость разбора ClientKeyExchange ко времени (Бляйхенбахер), середины рядов | мкс |
| TLS 1.2 ECDHE-ECDSA-GCM | рукопожатие 0xC02B, ECDSA P-256 из `tests/corpus` | раз/с |
| TLS 1.2 ECDHE-ECDSA-CBC | рукопожатие 0xC023 с порядком RFC 7366 | раз/с |
| TLS 1.2 ECDHE-PSK-CHACHA20 | рукопожатие 0xCCAC без сертификатов | раз/с |
| TLS 1.2 голый RSA-GCM | рукопожатие 0x009C: расшифрование RSA-2048 у сервера | раз/с |
| TLS 1.2 билет RFC 5077 | сокращённое рукопожатие по билету через `vault`/`resume` | раз/с |
| DTLS 1.3 / DTLS 1.2 рукопожатие | поверх дейтаграмм с просьбой подтвердить адрес, без потерь | раз/с |
| DTLS 1.3 / DTLS 1.2 записи 1200 байт | записи прикладных данных по одной в дейтаграмме, 1100 байт содержимого | МБ/с |
| AES-128-CBC-SHA256 ETM / MtE, AES-128-GCM | наложение и снятие защиты записи в 16 КиБ на `protect::protection_t` | МБ/с |
| OCSP разбор ответа, разбор и проверка | `ocsp::response_t::parse` и `ocsp::verify` ответа из `tests/corpus/ocsp` | раз/с |
| LZ77 сжатие / распаковка цепочки | частный кодек `sample/compress/lz77.hpp` на цепочке из трёх сертификатов | раз/с |
| TLS 1.3 цепочка из 3 / сжатая | рукопожатие с цепочкой ECDSA без сжатия и со сжатием RFC 8879 | раз/с |

Защита записей CBC меряется на самой `protect::protection_t`, а не на связи: пара наших
сторон при наборе CBC всегда согласует порядок RFC 7366, и порядок MAC-then-encrypt (тот,
что идёт за постоянное время против Lucky13) иначе не смерить.

Строки рукопожатий TLS 1.3 идут с кривыми обмена по умолчанию, а первой там стоит
ГОСТ-кривая в 512 разрядов (`GC512C`) - доля ключа вырабатывается по ней, и оттого
рукопожатие 1.3 в наборе на порядок медленнее строк 1.2, где кривая задана `X25519`.
Сличать эти строки между собой нельзя: они меряют разные кривые, а не разные издания.

### ChaCha20-Poly1305 и SHA-512 после ускорений (06.09.2026)

ChaCha20 получил векторные ветви - по четыре блока разом у NEON (ARM64) и SSE2/SSSE3
(x86-64), по восемь у AVX2, - Poly1305 складывает блоки парами по разделу 2.5.1
RFC 8439, SHA-512 идёт командами ARMv8.2. Всё с выбором на исполнении по
`sys/machine.hpp`; запрет `ANTS_MACHINE=0` возвращает переносимые пути. Лучшее из
шести прогонов, эталон - OpenSSL 3.6.3 тем же набором:

| Работа | До | После | Эталон | Отношение после |
| --- | --- | --- | --- | --- |
| ChaCha20 | 754,5 МБ/с | **1813,7 МБ/с** | 2973,1 МБ/с | 0,61 |
| ChaCha20-Poly1305 | 582,1 МБ/с | **1324,0 МБ/с** | 2121,7 МБ/с | 0,62 |
| SHA-512 | 595,4 МБ/с | **1660,8 МБ/с** | 1735,7 МБ/с | 0,96 |

Разбор, числа x86-64 и оговорки - в [COMPARISON.md](COMPARISON.md), раздел «ChaCha20-Poly1305:
векторные ветви», и в [DIGEST-SPEED.md](DIGEST-SPEED.md).

### Почему рукопожатие не сличается с OpenSSL

Эталон здесь - только `libcrypto`: хеши, шифры, подпись и обмен ключами меряются
против работы того же рода, а рукопожатие TLS 1.3 сличается ни с чем и прежде не
сличалось. Приёма «тот же сценарий у эталона» для рукопожатия нет, и заводить его
для издания 1.2 пришлось бы с нуля: подключать `libssl`, вести обе стороны парой BIO в
памяти и уравнивать состав работы - эталон при рукопожатии проверяет ещё и цепочку
доверия, чего связь по замыслу не делает (решение остаётся за потребителем). Такое
сличение мерило бы разницу устройств, а не цену рукопожатия, и потому не добавлено;
обмен с настоящим openssl проверяется не замером, а проверками `Tls12Test.Interop` и
`Dtls12Test.Interop`.

## Сличение с ГОСТ у эталона

На стенде Astra Linux у OpenSSL подключён провайдер `gostprov` — там эталон несёт ровно
наши алгоритмы, и сличается одно и то же, а не работа одного рода. Хеши и шифры меряются
самим `openssl speed`:

```bash
openssl speed -provider gostprov -provider default -evp md_gost12_256
```

Подписи `openssl speed` не знает, и для неё рядом лежит щуп [gostbench.c](gostbench.c):

```bash
gcc -O2 -o gostbench gostbench.c -lcrypto && ./gostbench
```

Щуп подписывает готовый хеш через `EVP_PKEY_sign` — ту же работу, что мерит набор, —
и меряет обмен ключами VKO. Провайдер `gostprov` обмена ключами не объявляет вовсе:
VKO несёт унаследованный движок `gost.so`, а добавочное значение (UKM) ставится ему
старым `ctrl` с кодом `EVP_PKEY_CTRL_SET_IV`; строковый `ctrl` и `OSSL_PARAM` у него
не в ходу.

С 04.11.2026 сам набор тоже меряет ГОСТ-эталон: при наличии провайдера gostprov
(Astra) bench подгружает его и снимает эталонные ветви Стрибога, Кузнечика и Магмы
в CTR и MGM, а также подписи ГОСТ 34.10 той же кривой CryptoPro-A; на стендах без
провайдера весь блок пропускается с приметой. VKO провайдер не объявляет - его
по-прежнему снимает щуп gostbench.c.

Итоги сличения лежат в [COMPARISON.md](COMPARISON.md).
